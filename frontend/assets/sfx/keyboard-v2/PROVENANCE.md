## 权利状态

- 这批采样的**可商用性取决于那两段原始视频的授权**，不取决于本目录。
- 上游 README 原话：**「加重键是加工版，不能声称视频中实际录制了空格或回车」** ——
  `*-space.wav` / `*-enter.wav` 是把 `*-normal.wav` 提升 +3 dB / +4.5 dB 得到的，
  三者时长完全相同（黑轴都是 55.9 ms），只有峰值比例不同（40.0% / 56.5% / 67.2%）。
  任何对外描述都不能说"空格的音是从视频里单独录的"。

## 已做的响度归一（代码侧，不改文件）

实测 normal 键的 RMS 相差近 8 dB，直接并列会"一个炸一个虚"，所以在 `writer-modes.js` 里按套给了增益：

| 主题 | 实测 normal RMS | 归一增益 g | 说明 |
|---|---|---|---|
| black 黑轴 | −28.1 dBFS | 0.80 | 基准 |
| red 红轴 | −30.6 dBFS | 1.08 | 抬 2.6 dB |
| metal 金属 | −30.8 dBFS | 1.10 | 抬 2.8 dB，最薄 |
| electronic 电子 | −27.5 dBFS | 0.75 | 略压 |
| firecracker 鞭炮 | −22.5 dBFS | 0.42 | 压 5.5 dB，原本最响 |

统一再乘 0.8 的总闸门留出叠音余量：最重的 metal-enter 归一后峰值约 74%，不会削顶。

## 已知的听感风险（需要人耳验收）

1. **每套每个键只有 1 个采样**，快速连打会"机关枪"。代码里用 ±7% 的 `playbackRate` 抖动来打散，
   但这只能减轻、不能消除。真要自然，需要每套补 4~6 个变体。
2. **鞭炮 132 ms 偏长**，连打会糊成一片，已给它 28 ms 的 `minGap` 声部冷却；其余三套 14 ms。
3. 这批**没有经过人工听审**（上游 README 自己写了"尚未进行人工听审"）。
